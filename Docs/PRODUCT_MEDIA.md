# Product Media

RegProbe's public visuals should make the trust model obvious in under a minute. The goal is not glossy marketing first. The goal is a calm, truthful first impression that shows what the app does, what it blocks, and how rollback stays close.

## Current README Lane

The README now uses repo-local preview assets from `assets/product/`:

- `configuration-verdict-card.svg`
- `evidence-detail-drawer.svg`
- `recovery-surface.svg`
- `preview-apply-verify-rollback.gif`

These assets are intentionally lightweight and reproducible. They are generated from the current product language so the public preview does not drift from the shipped UI vocabulary.

## Source Of Truth

The current preview assets are generated by:

```bash
python3 scripts/generate_product_preview_assets.py
```

That script refreshes the SVG preview panels and the README storyboard GIF.

## What Public Media Must Show

Every public screenshot or demo should make these ideas visible:

- preview before apply
- verdict and evidence snapshot language
- risk and rollback close to the action
- recovery as a first-class surface
- the app's calm separation between browsing, mutation, and verification

## Truth Rules

Public media should stay honest.

- Only show shipped surfaces or clearly labeled preview concepts.
- Do not imply a setting is recommended if the current verdict is blocked or research-only.
- Do not crop out the trust signals just to make the UI look cleaner.
- Prefer real product language over invented marketing language.
- Hide machine-specific identifiers, usernames, and local paths before publishing.

## When To Refresh

Refresh product media when one of these changes lands:

- tweak-row trust language changes
- verdict or evidence snapshot labels change
- Recovery surface changes materially
- navigation labels change
- release notes claim a calmer or safer product story than the README visuals currently show

## Release Upgrade Path

The current lane is intentionally repo-local and reproducible. For a release-grade refresh, replace or augment these assets with real Windows captures:

1. Tweaks surface with the verdict card visible
2. Evidence detail drawer or side panel
3. Recovery surface with rollback visible
4. A short GIF that shows preview -> apply -> verify -> rollback

When that happens, keep the same asset names if possible so the README does not need a second round of churn.
